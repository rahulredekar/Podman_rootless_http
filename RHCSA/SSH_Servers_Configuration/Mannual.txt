Here’s a practical production-focused SSH hardening guide for both Red Hat Enterprise Linux and Ubuntu servers — starting from basic protection to advanced enterprise-grade hardening.

---

# 1. Check SSH Service Status

## RHEL 9

```bash
sudo systemctl status sshd
```

## Ubuntu 24

```bash
sudo systemctl status ssh
```

Enable at boot:

```bash
sudo systemctl enable sshd
```

Ubuntu:

```bash
sudo systemctl enable ssh
```

## RHEL 9

```bash
sudo dnf install openssh-server -y
```

## Ubuntu 24

```bash
sudo apt update
sudo apt install openssh-server -y
```

# 3. Backup SSH Config Before Changes

```bash
sudo cp /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
```

Production rule:

* Always backup before editing
* Always keep one active SSH session open

# 4. Edit SSH Configuration

```bash
sudo vi /etc/ssh/sshd_config
```

or

```bash

```

# 5. Basic Secure SSH Settings

Add or modify:

```bash
Port 2222
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
PermitEmptyPasswords no
MaxAuthTries 3
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2
UsePAM yes
X11Forwarding no
AllowTcpForwarding no
```

Description:

| Setting                     | Purpose                          |
| --------------------------- | -------------------------------- |
| `Port 2222`                 | Reduce automated scans           |
| `PermitRootLogin no`        | Disable root SSH login           |
| `PasswordAuthentication no` | Force SSH key usage              |
| `PubkeyAuthentication yes`  | Enable key-based auth            |
| `MaxAuthTries 3`            | Limit brute-force attempts       |
| `LoginGraceTime 30`         | Timeout unauthenticated sessions |
| `X11Forwarding no`          | Disable GUI forwarding           |
| `AllowTcpForwarding no`     | Prevent SSH tunnel abuse         |

---

# 6. Create SSH Key Pair

On client machine:

```bash
ssh-keygen -t ed25519 -a 100
```

Recommended modern algorithm:

* `ed25519`
* Faster and stronger than RSA

Files:

```bash
~/.ssh/id_ed25519
~/.ssh/id_ed25519.pub
```

---

# 7. Copy SSH Key to Server

```bash
ssh-copy-id -p 2222 user@server-ip
```

Manual method:

```bash
cat ~/.ssh/id_ed25519.pub
```

Paste into:

```bash
~/.ssh/authorized_keys
```

Correct permissions:

```bash
chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
```

# 8. Restart SSH Service

## RHEL 9

```bash
sudo systemctl restart sshd
```

## Ubuntu 24

```bash
sudo systemctl restart ssh
```

Validate config before restart:

```bash
sudo sshd -t
```

Very important in production.

# 9. Configure Firewall

## RHEL 9 (firewalld)

Open custom SSH port:

```bash
sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --reload
```

Remove default SSH:

```bash
sudo firewall-cmd --permanent --remove-service=ssh
sudo firewall-cmd --reload
```

---

## Ubuntu 24 (UFW)

```bash
sudo ufw allow 2222/tcp
sudo ufw delete allow 22/tcp
sudo ufw enable
```

Check:

```bash
sudo ufw status
```

# 10. SELinux Configuration (RHEL 9)

If changing SSH port:

Check SELinux mode:

```bash
getenforce
```

Add custom SSH port:

```bash
sudo semanage port -a -t ssh_port_t -p tcp 2222
```

If already exists:

```bash
sudo semanage port -m -t ssh_port_t -p tcp 2222
```

Install semanage tools:

```bash
sudo dnf install policycoreutils-python-utils -y
```

# 11. Restrict SSH Users

Only allow specific users:

```bash
AllowUsers admin devops
```

Or groups:

```bash
AllowGroups sshusers
```

Create group:

```bash
sudo groupadd sshusers
sudo usermod -aG sshusers username
```

# 12. Advanced SSH Key Restrictions

In `authorized_keys`:

```bash
from="10.0.0.5",command="/usr/local/bin/backup.sh",no-port-forwarding,no-agent-forwarding ssh-ed25519 AAAA...
```

Description:

| Option                | Purpose             |
| --------------------- | ------------------- |
| `from=`               | Restrict source IP  |
| `command=`            | Force command       |
| `no-port-forwarding`  | Disable tunnels     |
| `no-agent-forwarding` | Prevent agent abuse |

# 13. Fail2Ban Protection

## Ubuntu

```bash
sudo apt install fail2ban -y
```

## RHEL

```bash
sudo dnf install fail2ban -y
```

Enable:

```bash
sudo systemctl enable --now fail2ban
```

Create jail config:

```bash
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
```

Edit:

```bash
sudo vi /etc/fail2ban/jail.local
```

SSH section:

```ini
[sshd]
enabled = true
port = 2222
maxretry = 3
findtime = 10m
bantime = 1h
```

Restart:

```bash
sudo systemctl restart fail2ban
```

Check bans:

```bash
sudo fail2ban-client status sshd
```

# 14. Disable Weak Ciphers & Algorithms

View supported:

```bash
ssh -Q cipher
ssh -Q mac
ssh -Q key
```

Production-safe example:

```bash
Ciphers chacha20-poly1305@openssh.com,aes256-gcm@openssh.com
MACs hmac-sha2-512-etm@openssh.com
KexAlgorithms curve25519-sha256
```

# 15. Multi-Factor Authentication (MFA)

Install Google Authenticator PAM module.

## Ubuntu

```bash
sudo apt install libpam-google-authenticator -y
```

## RHEL

```bash
sudo dnf install google-authenticator qrencode -y
```

Configure:

```bash
google-authenticator
```

Edit:

```bash
sudo vi /etc/pam.d/sshd
```

Add:

```bash
auth required pam_google_authenticator.so
```

Edit sshd config:

```bash
ChallengeResponseAuthentication yes
AuthenticationMethods publickey,keyboard-interactive
```

Restart SSH.

```bash
vi ~/.ssh/config
```

Example:

```ini

    HostName 10.0.0.10
    User admin
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

Connect:

```bash
ssh prod-server
```

```ini
Port 2222
Protocol 2

MaxAuthTries 3
LoginGraceTime 30

ClientAliveInterval 300
ClientAliveCountMax 2

X11Forwarding no

UsePAM yes
AuthenticationMethods publickey

LogLevel VERBOSE
```

Validate:

```bash
sudo sshd -t
```

Reload safely:

```bash
sudo systemctl reload sshd
```

# 26. Emergency Recovery Tips

If locked out:

Boot into rescue mode and fix:

```bash
/etc/ssh/sshd_config
```

Common mistake:

```bash
PasswordAuthentication no
```

before SSH keys are installed.

Always test in second session first.
